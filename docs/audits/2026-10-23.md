# Project audit, October 23, 2026

The audit started from `5846501e93808be3f275dc70f1a01812a5b947d8`.
Independent agents reviewed the complete application source, backend,
frontend, tests, build configuration, deployment configuration, and maintenance
setup with PStack, Ponytail full, and Thermo-Nuclear guidance.

## Findings and changes

- Vite 8.3.2 had six known advisories, with a highest severity of high.
  Upgrade to 8.3.5 and regenerate its required transitive dependencies.
  These advisories affect development tooling. The audit did not demonstrate
  an exploit against the deployed site. See the
  [security fixes](https://github.com/vitejs/vite/releases/tag/v8.3.3) and
  [selected patch release](https://github.com/vitejs/vite/releases/tag/v8.3.5).
- Dependency version proposals were not configured. Add npm and GitHub Actions
  checks every Monday at 06:00 Europe/London, matching Speye's schedule.
  Group minor and patch npm updates. Keep major npm proposals separate and
  retain security-update eligibility. Version proposals start after the
  configuration reaches the default branch.
- Dependabot alerts and security updates were disabled. Enable both through
  GitHub's API and read back their enabled state. These settings are separate
  from the weekly version-update configuration.
- CI did not enforce dependency vulnerability results. Add
  `npm audit --audit-level=high`, including development dependencies.
- `main` had no protection. Require an up-to-date **Verify site and Worker**
  check from GitHub Actions, enforce it for administrators, and require resolved
  review conversations. Force pushes and branch deletion remain disabled.
  Automatic merging remains disabled. No approving-review count is required.

The initial build correctly failed because untracked Finder metadata in
`public/.DS_Store` was copied into the public output. Removing the local
metadata restored the existing asset-boundary check. The check was not relaxed.

The source review found no supported application defect requiring an
additional runtime change. The existing architecture, design, pollers,
accessibility behavior, validation, cache policy, and security headers remain.

## Local verification

Both the baseline and updated branch passed under Node 24.22.1:

- `npm run check`, including formatting, generated Worker types, all strict
  TypeScript configurations, production build, and 157 unit/build tests.
- `npm run test:browser`, with 160 Chromium and WebKit tests passing without
  retries. Coverage includes themes, hydration, layout, keyboard focus,
  playback updates, error recovery, reduced motion, callback privacy,
  development CSP/HMR, methods, CORS, and asset isolation.

The updated branch also passed a clean `npm ci`, Wrangler deployment dry-run,
`npm audit --audit-level=high` with zero advisories at any severity,
`npm ls --all`, manifest/lockfile consistency checks, Dependabot JSON schema
validation and schedule/group assertions, `actionlint`, and `git diff --check`.
The new audit command rejects the baseline's high advisory and accepts the
patched dependency tree.

## Material limits

The canonical custom-domain challenge did not complete in the automated
browser. Rendering checks used the direct Worker URL. No Cloudflare security
setting was relaxed. The HTTP probe received a Python-client 403 and passed
with curl; neither result was treated as a source-code defect.

Live Spotify authentication faults and provider rate limits were not forced.
Deterministic tests cover these cases. No manual screen-reader audit was
performed. Future dependency proposals and the patched production release
cannot be confirmed before the PR reaches the default branch.

Finite tests and independent review support the exercised behavior. They do
not prove universal correctness across every future browser or provider state.
